# Official 9B on one Radeon AI PRO R9700

This work adds measured projection choices for the official
`StartLux-Decision-v1.1-9B-AutoThink-Q4_K_M.gguf` checkpoint. Qualification is
specific to gfx1201, Torch `2.14.0+rocm10.1.0`, Triton
`3.8.0+git669b31ac.rocm10.1.0`, and HIP `7.16.26385` in the locked ROCm 10.1 image.
The checkpoint SHA256 is
`c10277820051d4f29654566e94489e0add4ca3e2c5e49e4171ac53c8cf37adc8`.

**Qualification complete for the official 9B W4A16 text service on the locked
single-R9700 runtime.** W4A8 remains experimental. The independent operator
quarantines and other limits below remain explicit.

## What changes

The existing 9B shapes missed the tuning table. Decode batches up to eight fell
back to independent row GEMVs, whereas batch nine used a padded WMMA GEMM.
Per-shape selection now compares packed dot, WMMA, Q4 grouped loops, and Q6 scaled
WMMA together. A candidate must retain the original output, valid-row masking,
residual update, and unwritten bytes. Runtime and kernel identity guards remain
active. Unknown or unqualified shapes retain the original fallback.

The W4A16 profile has a separate table of metadata configurations. Its candidate
checks include complete FP32 output bytes and an independent FP64 reference over
FP16 inputs and decoded FP16 weights. The existing numerical bound remains
`1e-5 + 5e-6 * sum(abs(x*w))`. Some original WMMA results exceed that bound;
those keys are explicitly quarantined from optimization, retain the original
path, and are not reported as independently certified operators. CPU/GPU FP64
and a minimal direct WMMA experiment distinguish this original accumulation
behavior from a candidate arithmetic change.

No new arithmetic kernel, expanded weight representation, reduced vocabulary,
or multiple-GPU execution is required by these table choices. The full
generation head remains resident in decode and service measurements.

## Numerical status

On the frozen 501-task main set and 20-task held-out set, final-source 9B W4A16 passes
probability MAE <= 0.001, P99 <= 0.01, and clear-margin decision agreement >= 99.5%.
Main-set MAE is 0.0000597279 and P99 is 0.0004612304; held-out MAE is
0.0000243827 and P99 is 0.0001892252. Both decision agreement rates are 100%.
W4A8 fails the main probability thresholds even when candidate outputs exactly
match the original W4A8 implementation. Its speed results are experimental and
must not be combined with W4A16 accuracy into a single claim. The reference uses
independent FP32 computation with the same quantized GGUF weights; it does not
measure quality against an unquantized checkpoint.

The separate 27B regression retains both original tables' entries and reproduces
the historical per-case probabilities. W4A16 passes both probability sets;
W4A8 fails the main set. Four paired 27B decode points (both profiles, B1/B8)
change by less than 0.2%. This is model regression evidence, not a newly qualified
27B default service.

## HTTP measurements and remaining limits

The final W4A16 eight-slot configuration replays 1,840 measured requests against
the frozen original-table service. Request bodies, semantic answers, thought
content and token usage match exactly. No measured scene has a P50/P95
regression flag. Examples: `readme3` P50 changes from 470.91 to 61.49 ms;
the mixed scene changes from 2.298 to 14.044 requests/s, with P95 from
9346.45 to 1591.22 ms. Request counts below 200 have no formal P95 claim.

Actual thinking output throughput at client concurrency 1/8/16 is
50.85/172.35/191.01 tokens/s, compared with 13.63/35.83/36.22 for the original
table. Output totals remain 1,629/1,744/3,440 tokens. These are HTTP measurements,
not fixed-active-batch decode measurements.

Readout concurrency 16 still performs worse than concurrency 8: 9.249 versus
16.636 requests/s. Recorded median packed/read buckets grow from 1536/32 to
4096/64, and stream elapsed time increases. This is a remaining prefill/service
limit, distinct from the corrected decode B8/B9 dispatch cliff. Static expansion
of the measured service buckets finds 195 qualified table keys and 15 quarantined
original-path keys, with no unknown shape fallback. It is not a new kernel trace
or an independent certification of the quarantined keys.

## Reproducing a table experiment

All GPU commands must run with exactly one verified device visible. Freeze the
checkpoint, tokenizer, source, runtime, requests, and cache identity before an
experiment. Use a new output directory and compiler cache for each candidate.

1. Capture a state-reset decode baseline with `bench/amd_model_ab.py --capture`.
   For a real decode-only fixture, also use `--capture-decode-only`.
2. Capture per-layer real readout inputs and an ordered projection stream with
   `bench/amd_projection_replay.py --capture`. `--service-trace` adds the actual
   prefill/readout buckets found in a completed service run.
3. Run `bench/amd_real_shape_tune.py` for W4A8 or
   `bench/amd_real_w4a16_tune.py` for W4A16. Both record seven paired cold, hot,
   and partial-row trials. W4A16 `--quarantine-reference-failures` records an
   original-reference failure and retains that key's fallback; it never relaxes
   the bound or certifies the failed key.
4. Use `bench/amd_build_table.py` to select candidates within one qualified
   experiment. Conflicting legacy family results are rejected. If a key has
   multiple independently measured inputs, `select_fixtures` requires every
   input to pass the same thresholds before ranking normalized gains.
5. Use process-local `--table label:path` overrides in
   `bench/amd_model_ab.py` and `bench/amd_readout_ab.py`. These check runtime and
   kernel identity. Each model mode has separate graph state. Do not install a
   table until model equivalence and regression gates pass.
6. Re-run the final batch/context/graph matrix, probability suites, HTTP
   measurements, and sustained load on the exact installed source.

`bench/amd_dispatch_report.py` explains missing tables, runtime or kernel
mismatches, unknown shapes, and rejected layouts outside the timed path. Runtime
inference does not tune kernels or read a device row count back to the host.

## Reading the measurements

The reset protocol uses a 512-token prompt, eight warmup steps, 64 timed steps,
greedy generation, and five alternating paired rounds. All 72 generated tokens
and complete vocabulary logits at steps 0, 8, 32, and 71 are checked for every
sequence. Official `bench/decode_speed.py` results use its own unmodified protocol
and are reported separately.

At fixed active batch B, total tokens/s is `1000 * B / step_ms`; per-sequence
speed is `1000 / step_ms`. HTTP throughput instead uses actual completed requests
and actual output tokens, with queue and request latency reported separately.
Formal P95 comparisons require at least 200 completed requests. Shorter thought,
long-input, and cache trials report medians only. Client concurrency is a cap;
each timed round must contain at least that many requests.

Actual HSACO, register/private-memory resources, cold/hot behavior, and ordered
layer replay help explain results. The available performance counters failed
control validation, so these results make no DRAM saturation or dynamic WMMA
utilization claim. Static instruction counts are not utilization measurements.

## Capacity definitions

The qualified text service uses an 8192-token total context limit and a server
thinking-budget cap of 256 tokens. For a thinking request, the rendered prompt
plus its allowed continuation must fit the total context limit. An 8192-token
readout measurement uses `think_mode=never`. It does not establish that a full
8192-token prompt can also generate 256 tokens under the same service limit.

The long-context decode benchmark explicitly reserves `prompt_length + 256`
positions per sequence to measure its fixed 72 output steps. Its 8192-prompt
results therefore use that declared benchmark capacity, and are reported
separately from the default HTTP service. Neither configuration uses CPU
inference offload or a second GPU.

## Reverting

Set `STARTLUX_PRISM_AMD_GEMM=reference` for the W4A8 generic reference or
`STARTLUX_PRISM_AMD_W4A16=reference` for the original W4A16 projection path before
constructing a new engine. Reverting to the original automatic table requires
restoring that table and restarting the process. Existing captured graphs must
not be reused across a table/profile change.

No NVIDIA GPU was available for this qualification. Production changes in this
work are confined to AMD table data; unchanged NVIDIA source is a scope check,
not an NVIDIA runtime test. Visual inputs are outside this 9B text qualification.

Both checkpoints and both precision profiles also pass 512 complete-vocabulary
byte comparisons across fixed-seed sampled batches, reversed order and single
requests (four prompts, 16 steps, all 248,320 logits). These same-profile state
checks are separate from the independent FP32 probability gate.

## Qualified service configuration and operation

After scans and full confirmation, the selected configuration is `incumbent`: 8 thinking slots, an 8192-token batching budget, overlap threshold 1024, graph maximum 2048, and 4 prefix entries (4096 cache tokens). Total context/max_tokens remains 8192 and each thought is capped at 256 tokens. Default thinking mode is auto. No independently measured configuration changes were combined.

The selected configuration was confirmed on all original HTTP scenes, including 8192-token readout and mixed short/long/thought traffic. Semantic answers, thought content and token usage are identical; overall and class-specific latency gates pass. A batching budget limits groups per submission, not the context or output budget. One long request can still be submitted alone.

| Final default scene | P50 ms | P95 ms (at least 200 samples) | Requests/s |
|---|---:|---:|---:|
| readme3 | 61.49 | 62.22 | 16.130 |
| concurrency-8 | 475.84 | 569.69 | 16.636 |
| concurrency-16 | 1696.31 | 3047.88 | 9.249 |
| mixed-short-long-thought | 296.09 | 1591.22 | 14.044 |

The scan provisionally selected budget4096, which improved concurrency-16 readout from 9.249 to 18.640 requests/s in full confirmation. However, thought-16 P50 increased from 2314.709 to 2591.920 ms (+11.98%) with the same 3440 output tokens. The frozen conservative rule therefore retained the incumbent rather than promoting a configuration with an unresolved latency flag. The earlier scan had only a 3.24% P50 change; this does not establish a repeatable causal regression, and the scoped readout gain is not claimed as the default service result.

Sustained qualification covers 1800.18 seconds of actual mixed load, 16,084 requests and zero unexpected request errors. An explicit readout after client completion drains preceding work and reproduces the pre-load answer. Retained allocated growth is 0.000 MiB (limit 256 MiB); sustained peak allocated is 11.964 GiB (limit 28 GiB). Cache eviction, dynamic requests, budget termination, invalid input and recovery after client disconnection are covered. The endpoint does not provide immediate cancellation: accepted disconnected work drains normally.

The workspace launcher reaches health readiness in 57.56 and 12.01 seconds with empty and existing JIT caches. OS file-page cache is warm/uncontrolled. A real shell-launch/host-HTTP probe also passes, including owned shutdown. Omitted think_mode agrees with explicit auto for gate=0/1 on both process starts.

The workspace delivery includes `scripts/amd/serve_r9700_9b.sh` and its Python verifier. They bind the exact runtime, checkpoint, tokenizer, source, table and server arguments, and derive a separate JIT cache identity. This machine-specific entry selects tested physical GPU0; other card mappings need separate qualification. The wrapper is delivered with the workspace evidence, not installed by the table-only production change. Generic use of the model still requires one visible device and the declared runtime/capacity.

Application errors and selected-device telemetry show no observed GPU fault. Direct kernel-log access is unavailable under the existing permissions, so this is not a kernel-log audit. One historical non-timed fixture-capture exit sample has missing cgroup ownership. Adjacent owned-PID and VRAM-release evidence supports a narrowly reviewed exit-race inference; the raw unknown record and its reasoning remain preserved. Other unknown or foreign process samples still block qualification. The newer upstream FP8 KV implementation is outside this frozen-source qualification and must be qualified again on its actual integration base before transferring these claims.
