# AMD Instinct MI355X

The ROCm backend supports CDNA 4 (`gfx950`) execution on MI355X, using portable
arithmetic shared with the separate [Radeon work](https://github.com/StartLuxLabs/StartLux-Prism/pull/19).
Other ROCm architectures are rejected. CUDA extensions,
NVIDIA tuning tables, PDL and NVIDIA symmetric-memory kernels are bypassed on ROCm. MI355X projections use
portable Triton kernels; tensor parallelism uses RCCL for exact integer sums and
row maxima, with a final collective protecting shared staging buffers.

The [27B INT8 performance report](mi355x_performance.md) records the measured
ceilings, projection traffic, qualified tile selection and end-to-end latency.
The [next-version results](mi355x_next_version_results.md) record the newer GDN
improvements and experimental native MXFP4 work, including failed recipes.

## Experimental native MXFP4

The explicit `mxfp4` profile consumes the original 27B AutoThink BF16 safetensors
directory. Its default recipe uses paired 32-value rotations, E2M1 payloads and
E8M0 scales for all large projections. Norms, recurrent state, embedding and
decision readout retain their validated higher precision. This is separate
from GGUF Q4_K_M, W4A8 and W4A16. It is currently limited to single-GPU causal
text decisions and at most 16,384 packed tokens; decoding, vision and tensor
parallel FP4 have not been qualified.

```bash
M=../models/StartLux-Decision-v1.1-27B-AutoThink
docker build -f Dockerfile.rocm -t startlux-prism:mi355x-next .
STARTLUX_PRISM_ROCM_IMAGE=startlux-prism:mi355x-next \
  HIP_VISIBLE_DEVICES=0 scripts/serve_mi355x.sh "$M" . \
  --precision mxfp4 --max-tokens 4096 --graphs --graph-max-tokens 1536 \
  --prefix-cache 0 --mmproj none --think-mode never
```

Offline conversion, inside the matched ROCm environment:

```bash
python3 -m startlux_prism.tools.convert_mxfp4 --model-dir "$M" \
  --out "$M/mxfp4-r32" --components all --scaling ceil --rotate
```

Add `--mxfp4-artifact /models/mxfp4-r32` to the helper command to load that
artifact. Source BF16 files remain required. The manifest checks source,
recipe, shapes and file checksums. The public quality screen matches BF16's
213/231 score; broader quality and the 12 ms primary HTTP target remain open.
The current-tree FP4-only recheck records 14.69 ms p50 / 14.74 ms p95 for
`readme3` across 500 calls. It confirms the baseline on another MI355X; it is
not a paired speedup measurement. See [parts 14–15 of the execution report](mi355x_next_version_results.md#part-14-current-runtime-fp4-rebaseline)
for all five suites, profiling scope and the next optimization priorities.
Keep this profile opt-in while those gates are being completed.

## Run

The tested image pins AMD's PyTorch container by digest in `Dockerfile.rocm`:
Python 3.12, PyTorch `2.14.0+rocm10.1.0`, `torch.version.hip=7.16.26385`, Triton
`3.8.0`. The host has ROCm 7.1.0 and MI355X GPUs with 288 GiB each. The host Python
environment is not modified. AMD lists MI355X as
[`gfx950`, CDNA 4](https://rocm.docs.amd.com/en/latest/about/release-notes.html).

From this worktree:

```bash
docker build -f Dockerfile.rocm -t startlux-prism:mi355x .
M=../models/StartLux-Decision-v1.1-4B-AutoThink
HIP_VISIBLE_DEVICES=0 scripts/serve_mi355x.sh "$M" \
  StartLux-Decision-v1.1-4B-AutoThink-Q4_K_M.gguf \
  --graphs --kv-fp8 --max-tokens 4096 \
  --think-seqs 2 --think-kv-rows 8192 --max-think-budget 256
```

The helper mounts the model directory read-only and preserves compilation and
calibration caches in the Docker volume `startlux-prism-mi355x-cache`.
It binds the server to localhost on port 8092; `--port` changes it.
`STARTLUX_PRISM_ROCM_IMAGE` and `STARTLUX_PRISM_ROCM_CACHE` override the image and
cache volume. It accepts the usual server flags. `--help` lists them.

The model directory must contain its GGUF and matching release configuration,
tokenizer and chat template. Include the matching `mmproj-*.gguf` for images.
Q8_0 selects INT8 automatically; Q4_K_M selects W4A8. `--precision bf16` and
`--precision w4a16` are explicit alternatives. W4A16 changes numerical semantics.
The downloaded models for this validation are in the sibling `../models` folder.

With a matched ROCm PyTorch/Triton installation outside Docker, install only
`requirements-rocm.txt`, then use the normal Python server command. PyTorch calls
HIP devices `cuda:0`, `cuda:1`, etc. Select HIP ordinals before starting Python;
management-tool GPU numbers can differ. Set `HIP_VISIBLE_DEVICES=0,2` and pass
`--tp 2 --gpus 0,2` to shard an INT8 model across those cards. The same container
can run `python3 -m startlux_prism.dp --gpus 0,2 ...` by overriding its entrypoint
with `--entrypoint python3`. TP supports model head counts divisible by its size.

## Validation on this machine

These are functional regression checks, not a throughput comparison. Compact
results and the [evidence index](../bench/results/README.md) are tracked. This
workspace keeps full runs, calibration files and logs outside the checkout at
`../artifacts/startlux-prism/2026-10-26/results/`; model files remain in `../models/`.

| Check | Observed result |
|---|---|
| Focused unit/regression suite | 33 tests and 11 subtests pass, including INT8 dispatch checks |
| Backend arithmetic, Q4_K/Q6_K, live-row masking, both epilogues | Exact CPU reference arithmetic; independent gguf-py dequantization passes |
| W8A8 projections and INT32 shard sums | Exact CPU products, including HIP graph replay and partial live buckets |
| W4A16 kernels | 36 configurations pass independent arithmetic, masking and tile checks |
| FP8 KV cache and causal/bidirectional attention | Pass upstream GPU tests, including INT8 attention scores and decode |
| AutoThink 4B, BF16 and INT8 | 11/11 fixed-question decisions agree with FP32; repeated runs deterministic |
| AutoThink 9B and 27B, INT8 | 11/11 fixed-question decisions agree with FP32 on each model; repeated runs deterministic |
| AutoThink 4B and 27B, W4A8 | Cache miss/hit, eviction, eager/graph replay and shared/unshared evidence agree bit for bit |
| AutoThink 4B, W4A16 | Cache and graph checks agree bit for bit within this precision profile |
| AutoThink decode, 4B INT8/W4A8 and 27B W4A8 | Two sequences, 16 steps each: teacher-forced top-1 agreement, exact batch isolation, seeded sampling |
| Vision, 4B W4A8 | 52/52 synthetic decisions; 1/2/8-image graph/cache/mixed-batch checks pass |
| HTTP, 4B W4A8 with graphs, FP8 and vision loaded | 32 requests from 8 clients match serial answers and usage; a forced thought respects the omitted 64-token budget |
| Data parallelism, two INT8 workers | Healthy router and both workers; 32 requests from 8 clients match serial answers and usage |
| INT8 tensor parallelism, 4B on 2 and 4 GPUs | All tested readouts, cache cases, decode logits/tokens, joins and seeded samples match one GPU bit for bit |
| INT8 tensor parallelism, 27B on 2 GPUs | The same regression cases match one GPU bit for bit |
| HTTP, two-GPU INT8 server in eager mode | Startup warm-up, 32 concurrent requests and a forced thought pass |
| Instant 4B, BF16 with graphs | 11/11 fixed-question decisions agree with FP32; deterministic |
| Instant 4B, INT8 with graphs | Deterministic, 10/11 decisions agree; see numerical limits below |

Tensor-parallel regression uses `tests/test_tp.py` with six local synthetic
fixtures made from `bench/suites.py`, including long evidence. It checks complete
letter logits, cache hits, mixed batches, wide choices, greedy decode, joining a
running batch and seeded sampling. This is not the public JevBench evaluation.

## Reproduce

Run from a ROCm environment with the repository mounted. Optional test packages
are `pytest` and `gguf==0.19.0`. Use one visible card for single-GPU commands.

```bash
OUT=../artifacts/startlux-prism/mi355x-validation
HIP_VISIBLE_DEVICES=0 python3 -m pytest -q \
  tests/test_mi355x.py \
  tests/test_decode_graph_capture.py tests/test_eager_warmup.py \
  tests/test_scheduler_timings.py tests/test_think_budget.py tests/test_mi355x_dispatch.py \
  tests/test_mxfp4.py tests/test_mxfp4_artifact.py tests/test_mxfp4_dispatch.py
HIP_VISIBLE_DEVICES=0 python3 tests/test_amd_backend.py
python3 tests/test_amd_backend.py --cpu
HIP_VISIBLE_DEVICES=0 python3 tests/test_amd_w4a16.py
HIP_VISIBLE_DEVICES=0 python3 tests/test_bidir.py
HIP_VISIBLE_DEVICES=0 python3 tests/test_kv_fp8.py
HIP_VISIBLE_DEVICES=0,2 torchrun --standalone --nproc-per-node=2 \
  scripts/amd/test_mi355x_collectives.py
python3 scripts/amd/test_mi355x_http.py --url http://127.0.0.1:8092 \
  --think --output "$OUT/mi355x-http.json"
python3 scripts/amd/make_tp_fixtures.py --output "$OUT/tp-fixtures"

# Set M/G to the model folder and GGUF in the current environment.
HIP_VISIBLE_DEVICES=0 python3 tests/test_engine.py --gguf "$G" --model-dir "$M" \
  --precision int8 --max-tokens 4096 --no-graphs --repeat 1
HIP_VISIBLE_DEVICES=0 python3 scripts/amd/test_graph_cache.py \
  --gguf "$G" --model-dir "$M" --output "$OUT/mi355x-graph-cache.json"
HIP_VISIBLE_DEVICES=0 python3 scripts/amd/test_decode_model.py \
  --gguf "$G" --model-dir "$M" --graphs --tokens 16 \
  --output "$OUT/mi355x-decode.json"

# Q8_0, using the calibration file measured for this model:
python3 tests/test_tp.py --gguf "$G" --model-dir "$M" --calib "$CALIB" \
  --tp 2 --gpus 0,2 --ref-gpu 4 --jevbench "$OUT/tp-fixtures" --tokens 8
```

Use a Q4_K_M file for the default graph/cache/decode scripts; the decode script
also accepts `--precision int8` with Q8_0. Vision checks additionally take
`--mmproj FILE`. For full TP coverage, supply a calibration file and a public
JevBench dataset to `tests/test_tp.py` as described in that test's module docstring.

## Numerical and coverage limits

Functional execution does not establish 100% model-quality equivalence to FP32
or to NVIDIA. In the 4B Instant INT8 test, the changed decision had FP32 top
probabilities 0.4591 and 0.4456; its largest probability difference across all 11
questions was 0.07537. BF16 agreed on all 11. Quantized decode checks report
nonzero prefill/decode logit differences while checking top-1 and batch isolation;
the JSON files preserve those measurements. No numerical tolerance was relaxed.

The full graded accuracy suites, every release/precision/vision combination,
maximum context and image sizes, long-duration service stress and NVIDIA
hardware regression have not all been run. Radeon support and qualification
remain separate in [PR #19](https://github.com/StartLuxLabs/StartLux-Prism/pull/19). NVIDIA-specific microbenchmarks
remain NVIDIA tools. INT8 uses an offline MI355X table qualified for the exact
runtime and kernel source; unknown shapes retain the original Triton tile rule.
W4A8/W4A16 do not yet have MI355X performance tables.
